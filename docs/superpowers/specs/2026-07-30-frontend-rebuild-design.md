# price-compare-app フロントエンド全面刷新 設計

## 背景・目的

`price-compare-app`はスクレイパー・Supabase DB・実データ（3店舗5000件超）まで実装済みだが、フロントエンド（特に`PriceCompareReal.jsx`、1058行）は継ぎ足し開発で情報設計が複雑化している。UI/UX・情報設計を一から作り直し、あわせてお気に入り・値下げバッジの新機能を追加する。既存のスクレイパー・DBスキーマ・データはそのまま活用し、フロントエンド（LP含む）のみを刷新対象とする。

## スコープ

**対象**:
- LP（現行`LandingPage.jsx`／`index.html`）
- アプリ本体（現行`PriceCompareReal.jsx`／`app.html`）

**対象外**（現状のまま活用）:
- スクレイパー（`scraper/lib/aeon.js`・`scraper/lib/legacyPlatform.js`等）
- Supabase DBスキーマ・既存データ（`stores`・`products`・`store_products`・`price_history`等）
- LXC114（Proxmox）へのnginx静的配置というデプロイ方式

**技術スタックは現行維持**: Vite + React + lucide-react + プレーンCSS。Tailwind導入・Next.js移行は行わない。

## 機能構成

### 継続する既存3機能
- 買い物リスト比較（商品追加→店舗別合計金額を安い順にランキング表示）
- 最安値一覧（物の名前単位でカテゴリ別に一覧表示、クリックで個別商品展開）
- 地図ビュー（Leaflet、3店舗の位置表示）

### 新規機能A: お気に入り
- ログイン必須。Supabase Auth（既存`favorites`テーブルを使用）にお気に入り商品を保存し、複数端末で同期する
- **ゲストモード**: ログインしない状態でもアプリの閲覧・機能体験は可能。ただしお気に入り登録はその場限り（ページリロードで消える）で永続化しない。保存したい場合はログイン・新規登録を促すUIを出す

### 新規機能B: 値下げバッジ
- 判定基準: 対象商品が**直近30日間で最安値を更新**した日の価格のときにバッジを表示する
- 表示対象は`price_history`の日次データから、商品ごとに過去30日のレコードをさかのぼり、最新値がその期間内の最小値と一致（かつ厳密に前回より下がった）場合のみ表示する

### 見送り機能（将来タスク）
- 単価表示（¥/100g等）: 商品名からの量データ自動抽出は精度リスクがあるため今回は実装しない。`project.md`のタスクに残す
- Googleログイン（Phase B、後述）

## 認証設計

### Phase A（今回実装）: メール＋パスワード認証
- Supabase Authのメール/パスワードでの新規登録・ログインを実装
- インフラ変更が必要: 現在`.env`の`DISABLE_SIGNUP=true`（一般ユーザーの自己登録を無効化、管理者API作成前提の設定）を解除し、一般ユーザーの自己登録（メール確認込み）を有効化する
- ゲストモードとの切り替え: 未ログイン状態でもアプリ全機能を閲覧・試用可能。お気に入りボタン押下時のみ「ログインすると保存されます」という導線を出す

### Phase B（将来タスク・ブロック中）: Googleログイン追加
- **前提条件**: Zが自身でGoogle Cloud ConsoleにてOAuthクライアントID/シークレットを作成する必要がある（Claudeによる代行不可）。現時点で未取得
- Phase Aのメールログイン実装・リリースを先に完了させ、Zの認証情報作成が完了し次第、追加実装として着手する
- `projects/price-compare-app/project.md`の「タスク」セクションに追記する

## ビジュアル・ナビゲーション設計

### トーン: クリーン・ミニマル
- 白背景＋青（#2563eb系）アクセントカラー
- カード型UI、境界線は薄いグレー（#e2e8f0系）、角丸・余白多め

### ナビゲーション: レスポンシブ切替
- 画面幅が狭い場合（スマホ）: 下部固定ナビゲーションバー（最安値・比較・地図・お気に入りの4項目、アイコン＋ラベル）
- 画面幅が広い場合（PC・タブレット）: 左固定サイドバー（同じ4項目）
- ブレークポイントは実装時にVite/CSSの標準的なタブレット境界（768px前後）を基準に決定する

### 商品行デザイン: 「詳細」パターン
- お気に入り☆アイコンを常時表示（クリックでトグル）
- 値下げバッジは行の目立つ位置に固定表示（該当時のみ）
- 主要情報（物の名前・最安値）は1行目、補足情報（店舗数等）は2行目に小さく表示

## コンポーネント構成の見直し

現行`PriceCompareReal.jsx`（1058行）は単一ファイルに全機能が同居しているため、以下の単位に分割する:

- `ProductRow` — 商品行の見た目（お気に入り☆・値下げバッジ・価格表示）を集約する共通コンポーネント。一覧・展開表示の両方から再利用する
- `ListView` — 最安値一覧（カテゴリセクション・商品行一覧・展開ロジック）
- `ShoppingListCompare` — 買い物リスト比較（プリセット・LocalStorageカスタムリストは既存仕様を踏襲）
- `MapView` — 地図ビュー（Leaflet部分、現行実装をほぼそのまま移設）
- `FavoritesView` — お気に入り一覧（ログイン時のみ表示、Supabaseから取得）
- `AuthForm` — ログイン・新規登録フォーム（メール/パスワード）
- `AuthContext` — セッション状態（ログイン中/ゲスト）を各コンポーネントに供給する共通コンテキスト
- `AppShell` — レスポンシブナビゲーション（下部ナビ／サイドバーの出し分け）＋各ビューのルーティング

各コンポーネントは「何をするか・どう使うか・何に依存するか」が単体で説明できる粒度に保つ。データ取得（Supabase呼び出し）はビューコンポーネント側に閉じ込め、`ProductRow`等の表示コンポーネントはpropsのみに依存させる。

## データフロー

- 商品データ・価格データ: 既存の`anon`向けSELECTポリシーのある`stores`・`products`・`store_products`・`price_history`から直接fetch（変更なし）
- お気に入り: ログイン中のみ、`favorites`テーブルに対しユーザーIDに紐づくCRUDを実施。RLSポリシーを新設し、`auth.uid()`が一致する行のみ本人がSELECT/INSERT/DELETEできるようにする
- 値下げバッジ判定: フロントエンド側で商品ごとに過去30日分の`price_history`を取得し、クライアントサイドで最小値判定を行う（Supabase側にビュー/関数を新設するかはPhase A実装時に判断）

## テスト・確認方針

- 各コンポーネント分割後、ブラウザ実機（LXC114デプロイ前にローカル`npm run dev`）で以下を確認する:
  - ゲストモードでの閲覧・お気に入りボタンの非永続動作
  - メール新規登録→ログイン→お気に入り登録→リロード後も保持されることの確認
  - 値下げバッジが実データ上で意図通り表示される商品の確認（直近30日で最安値更新した商品を1件以上特定して検証）
  - レスポンシブ切替（ブラウザ幅を狭めてナビゲーションが下部固定に切り替わること）
- LXC114への再デプロイ後、LAN内から`http://192.168.11.114/`（LP）・`http://192.168.11.114/app.html`（アプリ）で最終確認する
