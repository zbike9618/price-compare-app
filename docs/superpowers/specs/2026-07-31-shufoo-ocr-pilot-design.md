# Shufoo!チラシOCRパイロット 設計

## 背景・目的

これまでのスクレイピングはネットスーパー（マルイ・イオン・ニシナ）限定で、常設カタログの価格を取得していた。マルナカ・ハローズ・天満屋ハピーズ等、ネットスーパーを持たない実店舗チェーンを比較対象に加えるため、チラシ集約サイトのチラシ画像からOCRで商品名・価格を抽出する方式を検証する。

- トクバイ(`tokubai.co.jp`)は`robots.txt`でClaude/Anthropic系クローラーを名指しで拒否しており対象外
- Shufoo!(`shufoo.net`)はクロール制限が緩く、チラシ画像へのアクセスも可能。ただしチラシはスキャン画像（タイル分割）で、商品名・価格を表すテキストデータやJSON APIは存在しない

## スコープ（今回はパイロット検証のみ）

- 対象店舗: マルナカ平井店（岡山県）1店舗のみ
- 目的: OCRパイプラインが実用に足る精度で動くかを検証する。精度が低ければ本格導入を見送る判断材料にする
- DB書き込みは行わない。抽出結果をコンソールログに出力し、Zが目視で精度を確認する「ドライラン」までを実装範囲とする

## 技術調査で判明したこと

- Shufoo!の店舗ページ(`https://www.shufoo.net/pntweb/shopDetail/{shopId}/`)には、そのお店の「掲載中チラシ」一覧が表示され、各チラシは`https://ipqcache2.shufoo.net/c/{yyyy}/{mm}/{dd}/{contentId}/index/img/thumb/thumb_sp.jpg`のようなサムネイルURLを持つ（`contentId`はチラシごとに固有の13桁前後の数値）
- 実際のチラシ本体画像は`.../index/img/{page}_{zoom}_{tile}.jpg`の形式でタイル分割されている（確認できた例: `0_100_0.jpg`, `0_100_1.jpg` の2タイルで1ページ分）。`page`はページ番号、`100`はズームレベル、末尾がタイル番号
- タイル番号・ページ番号ともに存在しないものは404を返すため、0から順に増やして404が出たら打ち切る形で列挙できる
- 一覧に出ていた「7枚」は7ページではなく、発行日の異なる7件のチラシ（別々のcontentId）を指す。1件のチラシが何ページあるかは個別に確認が必要

## パイプライン設計

```
1. 店舗ページを取得 → チラシ一覧（contentId・掲載日）を抽出
2. 各チラシについて:
   a. page=0から順に、tile=0,1,2...を404が出るまで取得
   b. 取得したタイルを画像結合ライブラリで縦に結合し、ページ単位の1枚画像を作る
   c. 次のpageも同様に404が出るまで繰り返す（そのチラシの全ページを画像化）
3. 各ページ画像に対してOCR（日本語）を実行し、テキストと座標（bounding box）を取得
4. OCR結果から「¥」「円」を含む価格パターンを検出し、価格に最も近い座標にあるテキストブロックを商品名候補とする
5. 既存の`scraper/lib/categories.js`のキーワード一致・ノイズ語フィルタで商品名候補を絞り込み、カテゴリを付与
6. 結果（商品名・価格・カテゴリ・元画像内座標）をコンソールに一覧出力するのみ。DB書き込みは行わない
```

## 技術選定

- **画像結合**: `sharp`（Node.jsで広く使われる画像処理ライブラリ、ネイティブバイナリ同梱でセットアップが簡単）
- **OCR**: `tesseract.js`（ブラウザ/Node双方で動くWebAssembly版Tesseract。日本語学習データ(`jpn.traineddata`)を指定して実行、追加のシステムインストール不要）
- 既存スクレイパー(`scraper/`)と同じディレクトリ構成に新規`scraper/lib/shufooOcr.js`・実行スクリプト`scraper/run-shufoo-ocr-pilot.js`を追加する

## 精度・期待値について

- 商品名候補の座標ベース推定はチラシのレイアウトが不規則なため誤検出が一定数出ることを前提とする
- 今回はDB書き込みをせず、ログ出力した抽出結果（商品名・価格・カテゴリ）をZが目視確認し、実用に足るかを判断してから次のステップ（DB投入・他店舗展開）に進むかを決める

## 完了の定義（このパイロットのゴール）

- マルナカ平井店の直近チラシ1件について、ページ画像化→OCR→商品名/価格抽出のログ出力までが一通り動作する
- 抽出結果をZに提示し、「本格導入する / しない」の判断材料を揃える

## テスト

- ユニットテストは対象外（外部サイトの実データに依存する検証スクリプトのため）。実行結果のログをもって確認する
