# ダッシュボード（ホーム）新設 設計

## 背景・目的
Zが実施したユーザーヒアリングから、以下の課題が判明した（7項目のUX改善リストの1つ目として着手）:
- 「単語しかユーザーは読まない」→説明文中心のUIは読まれない
- 「地図を最初に出すのは微妙」→現状アプリ起動直後は「最安値」タブがデフォルトだが、地図タブに切り替えた際の初期設定（比べる範囲設定）が煩雑
- 「他タブを集約して導線を整備したい」「LPの改善案と同じようにファーストビューを整備したい」

今回はこのうち、起動直後のホーム画面を新設し、各機能への入口をシンプルなカードボタンで整理する。地図タブ自体の初期設定スキップは別項目として後日扱う。

## スコープ
- 対象: price-compare-appのフロントエンド（`src/`配下）のみ。DB・スクレイパーは変更しない
- ナビゲーションに5つ目のタブ「ホーム」を追加し、アプリ起動時の初期画面にする
- 既存4タブ（最安値・比較・地図・お気に入り）の中身・機能は変更しない。ホームはあくまでそれらへの入口

## 構成
1. **サマリー行**（任意表示）: 今月の節約額（`savings.js`の`getMonthlySavings()`を流用）が0円より大きい場合のみ、ごく短い1行で表示（例:「今月の節約額 ¥1,200」）。0円なら非表示（情報過多を避ける）
2. **カードボタン（2×2グリッド）**: 各機能への大きなボタン。アイコン＋短い単語ラベルのみ、説明文は付けない
   - 🏷️「最安値を見る」→`view: "list"`
   - 🛒「買い物リストで比較」→`view: "cart"`
   - 📍「地図で探す」→`view: "map"`
   - ⭐「お気に入り」→`view: "favorites"`

## コンポーネント構成
- `src/pages/HomeView.jsx`（新規）: サマリー行＋カードボタン4枚を描画する。props: `onNavigate(view)`（クリック時に親の`setView`を呼ぶ）、`monthlySavings`（数値、`savings.js`から取得して親から渡す）
- `src/components/AppShell.jsx`（変更）: `NAV_ITEMS`の先頭に`{ id: "home", label: "ホーム", icon: Home }`を追加（lucide-reactの`Home`アイコン）
- `src/pages/PriceCompareReal.jsx`（変更）:
  - `view`の初期値（33行目 `useState(() => (loadRangeSetting() ? "list" : "map"))`）を、常に`"home"`を返すよう変更する。これにより「範囲未設定時にいきなり地図が開く」現象も副次的に解消される
  - `view === "home"`のとき`<HomeView onNavigate={setView} monthlySavings={getMonthlySavings()} />`を描画する分岐を、既存の4分岐（400行目 `view === "list"` 等）と同じ並びに追加する
  - 既存の4ビュー分岐（list/cart/map/favorites）はそのまま維持

## デザイントーン
- 既存のカードボタン（`ShoppingListCompare`のプリセットボタン等）と同じ角丸・配色（`ACCENT`カラー）に揃える
- カードは正方形に近い比率、アイコンを大きめ（28〜32px程度）にしてラベルは1行に収まる短い単語にする

## テスト
- `HomeView`はナビゲーション用の薄いコンポーネントのため、クリックで`onNavigate`が正しい`view`引数付きで呼ばれることをテストする（vitest + testing-library、既存コンポーネントテストと同じ方針があれば踏襲。無ければ`onClick`ハンドラの単体呼び出し確認に留める）
- 実際の見た目・レイアウトはブラウザでの実機確認（スマホ幅390px）で確認する
